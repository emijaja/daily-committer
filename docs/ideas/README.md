## I1. お参りのモチーフをもっと使う

アプリ名「Sanpai（参拝）」に合わせて、お参りのモチーフを見た目に取り入れる。

### 案

- **キャラクターの変更**：いまのナマケモノ（[../design/character.md](../design/character.md)）を、お参りにちなんだキャラにする
- **Today ページのイラストを更新**：①-a のヘッダー下のイラストを、お参りの場面にする

### 検討すること

- キャラは「変更」か「追加」か（ナマケモノの「ぼやく相棒」という役割・口調を引き継ぐか）
- 「毎日のお参り」と「習慣の記録」をどう重ねるか（例：記録＝お参り、連続記録＝願掛け、など）
- 変える範囲：Today のイラストだけか、オンボーディング・空の状態・丸アイコンまで変えるか
- いまの見た目（みんなの銀行風、[../design/visual-style.md](../design/visual-style.md)）と合うか
- 宗教的なモチーフの扱い方（特定の寺社を連想させすぎないか）

## I2. 日々のメモ

その日のひとことメモ（自分のぼやき）を残せるようにする。

### 目的

- **自分を知る**：日々のぼやきを書きためることで、自分の気分や考えのくせに気づけるようにする
- **振り返る**：あとから読み返して、その頃の自分をふり返れるようにする
- **過去の自分からインスピレーションをもらう**：過去のメモをランダムに表示する UI・画面を作り、ふと昔の自分の言葉に出会えるようにする

キャラが「ぼやく相棒」なのに対し、メモは「自分のぼやき」。キャラのぼやきと並べて見せると、コンセプトとつながる。

### 案

- **メモの入力**：記録画面から、その日のぼやきを書ける
- **ランダム表示**：過去のメモを1件ランダムに出す（例：記録画面のカード、専用の画面、引き直しボタン）。お参りのモチーフ（I1）と合わせて「おみくじ」として引く形も考えられる

### 検討すること

- メモの単位：1日に1つか、1日に何件でも書けるか（ぼやきなら何件でも、が自然か）
- 入力する場所：①（記録画面）か、②（記録の確認・修正）か
- 見返す場所：③ 振り返りの日付から開けるか、メモの一覧（日記のような時系列）を作るか
- ランダム表示の出し方
  - 出す場所：①に常に出すか、専用の画面か
  - 出す頻度：毎日1件固定（その日のおみくじ）か、何度でも引き直せるか
  - どのメモを選ぶか：完全にランダムか、「1年前の今日」「1か月前」などを優先するか
  - メモが少ないうち（はじめて間もない頃）の表示
- 書きたくなる工夫：キャラのぼやきへの返事として書く、などの入口
- プライバシー：人に見られたくない内容もあるので、画面に出す場所に気をつける
- 長さの上限、CSV の書き出しに含めるか
- データモデル（[../web/domain-spec.md](../web/domain-spec.md)）への追加

## I3. 習慣以外の一時的なタスク（今日の TODO）

習慣（くり返し）ではない、その日だけのタスクも記録画面で管理できるようにする。

### 検討すること

- 習慣とどう見分けるか（同じリストに混ぜるか、別のブロックにするか）
- 終わらなかったタスクを翌日に持ち越すか、その日で消すか
- 集計（「今日 2/3」・連続記録・草）に含めるか → 含めない方が習慣アプリとしての軸がぶれない
- 期日つき（今週中・今月中）も扱うか、今日だけにするか
- 「習慣アプリなのに TODO」がコンセプト（[../design/product-and-flow.md](../design/product-and-flow.md)）に合うか

## I4. Three Good Things（今日のよかったこと3つ）

その日にあった「よかったこと」を3つ書けるようにする。ポジティブ心理学で知られる習慣（Three Good Things）。

### 目的

- **よかったことに目を向ける**：一日の終わりに、小さなよかったことを思い出すくせをつける
- **振り返る**：あとから読み返して、よかった日々を思い出せるようにする

### 案

- **入力**：記録画面から、その日のよかったことを3つまで書ける
- **習慣として扱う**：「Three Good Things を書く」を1つの習慣にして、3つ書いたら達成にする

### 検討すること

- 日々のメモ（[I2](#i2-日々のメモ)）との関係：別の機能にするか、メモの書き方の1つ（よかったこと3つ）にするか
- キャラの「ぼやき」とのバランス：ぼやきのアプリでよかったことを書く、の対比をコンセプト（[../design/product-and-flow.md](../design/product-and-flow.md)）にどう位置づけるか
- 集計（「今日 2/3」・連続記録・草）に含めるか：習慣として扱うなら含める
- 3つに満たないとき（1つ・2つ）の扱い
- 見返す場所：⑥ 振り返りの日付から開けるか、一覧を作るか。ランダム表示（I2 の案）と合わせるか
- 入力のタイミングと通知：夜のリマインド（4-2 Web Push）で書くきっかけを作るか
- プライバシー、CSV の書き出しに含めるか、データモデル（[../web/domain-spec.md](../web/domain-spec.md)）への追加

## I5. 記録へのコメント（ひとこと）

習慣の記録に、その日のひとことコメントをつけられるようにする（例：「雨の中 5km」「3章まで。眠くて頭に入らず」）。

> **✅ 採用（2026-11-21）**：デザインは [../design/screens.md](../design/screens.md)「⑩ ひとこと」「量の習慣の操作」・⑧-a/⑧-b、仕様は [../web/domain-spec.md](../web/domain-spec.md) 2章 entry_notes・11章。Figma は「全画面」セクションの ⑩-a/⑩-b・①-a 参考。
> 未対応：③ 習慣の詳細の「ひとこと」一覧、③ の草の点、CSV の書き出し、キャラの反応、I2 のランダム表示との連携。

### 目的

- **記録に背景を残す**：数字やチェックだけでは残らない、その日の様子を書いておく
- **習慣ごとに読み返す**：③ 習慣の詳細で、その習慣の日誌のように読める
- [I2 日々のメモ](#i2-日々のメモ)との違い：I2 は「1日に1つの自分のぼやき」、I5 は「習慣ごとの記録へのひとこと」。入力 UI と見た目は揃える

### 決めたこと（2026-11-21）

- **単位は（習慣, 日）に1つ**。entries の列ではなく別テーブルに持つ（チェックを外すと entries の行は消えるので、コメントを一緒に消さないため）
  ```
  entry_notes
    id, user_id, habit_id (FK), date (date), body (text), created_at, updated_at
    unique (habit_id, date)
  ```
  - 「回ごとに足す」の習慣も、1回ずつではなくその日全体に1つ
  - 週次・月次の習慣も、日付ごとに1つ（期間ごとにはしない）
- **未達成の日にも書ける**（「今日はやらなかった理由」も残せる）。コメントは集計・連続記録・草の達成には影響しない
- **入力は長押し**でひとことの入力シートを開く。長押しでは記録の状態は変えない（未記録のまま書ける）
  - チェックのみの習慣：□の長押し
  - 量の習慣：＋の長押し。今の「＋の長押し＝前回と同じ量で即記録」はやめて、記録の UI の別の操作に置き換える（下の「即記録の置き換え先」）
  - 「長押し＝ひとこと」をすべての習慣で揃える。ダブルタップは、1回目でチェックが入ってしまう・シングルタップの反応が遅くなるので使わない

### 即記録の置き換え先

**推奨**：⑧-a／⑧-b のシートに **「前回 25 回」チップ**を足す
- ⑧-a：チップの列（+1／+5／+10／目標の 30）に「前回 25」を足す。押すと値が 25 になる（ほかのチップと同じく、記録するのは黒のピル）
- ⑧-b：入力欄の上に「前回 3.2 km」チップ。押すと入力欄に入る
- 前回の記録がない習慣ではチップを出さない
- 1タップでの即記録はなくなり、「行か＋をタップ → チップ → 記録する」の3タップになる。量を確かめてから記録できるので、取り消しのトーストはいらなくなる

ほかの候補（採用しない理由）
- 行を右にスワイプで即記録：見つけにくい、縦スクロールとの判定が難しい
- 行に「前回と同じ」ボタンを常に出す：行が混む
- ＋のダブルタップ：ダブルタップを使わない理由と同じ

採用するときに直す所：[../design/screens.md](../design/screens.md)「量の習慣の操作」、[../design/product-and-flow.md](../design/product-and-flow.md) の画面遷移、[../web/domain-spec.md](../web/domain-spec.md) 10章、[../web/open-questions.md](../web/open-questions.md) B11・B12（？のヘルプの説明）、実装の `repeatLast`（`src/app/(main)/record/record-screen.tsx`・`review/[date]/day-edit-screen.tsx`）と `AddButton` の `onLongPress`

### 検討すること

- ⑧-a/⑧-b のシートにもひとこと欄を足すか（量と一緒に書けると便利。シートが縦に長くなる）
- 長押しの見つけやすさ：O2（タップで記録）や ？ のヘルプで教えるか、初めてチェックしたときにヒントを出すか
- 長押しの代わりの操作（アクセシビリティ）：② 記録の確認・修正の各行に💬ボタンを置くなど
- Web の長押しの実装：スマホのテキスト選択・コンテキストメニューを抑える。長押しの判定時間（500ms 前後）、指が動いたらキャンセル
- 入力シートの見た目：⑧ と同じボトムシート。日付・習慣名・テキスト欄・「保存」「削除」
- コメントがあることの表示：① の行に💬マークだけ出すか、本文を1行出すか（人に画面を見られる場面を考えると💬だけが安全）
- 見返す場所：③ 習慣の詳細に「ひとこと」一覧（新しい順・達成状態つき）、③ の草のコメントがある日に点
- 長さの上限（140字程度）、CSV の書き出しに含めるか、習慣の削除で一緒に消す（cascade）
- あとから：キャラがコメントに反応する、I2 のランダム表示（おみくじ）に混ぜる
