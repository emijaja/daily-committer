# データモデルと計算ロジック（下書き）

デザイン（`docs/design/`）に書かれていない部分を仕様にしたもの。
**【再検討】** は今の内容で進めるが、あとで見直す項目。一覧は [open-questions.md](open-questions.md)。

## 1. 基本方針

- 記録は「どの習慣を・どの日に・どれだけ」の**生のデータ**だけを保存する。連続記録・達成・草はすべて記録から計算する（保存しない）。
  - こうしておくと、週の始まりの変更や判定ルールの変更を、過去のデータにもそのまま反映できる。
- 日付はユーザーの「1日」（3章）で決まる**日付**（`DATE` 型）で持つ。日時（timestamp）は作成日時などの補助にだけ使う。

## 2. テーブル

Auth.js が使うテーブル（`users`、`accounts`、`sessions` など）は省略する。

### user_settings（ユーザーごとの設定）

| 列 | 型 | 内容 |
|---|---|---|
| user_id | FK → users | 主キー |
| timezone | text | 例 `Asia/Tokyo`。初回ログイン時にブラウザから取得する |
| week_start | enum `mon` / `sun` | 週の始まり（既定 `mon`） |
| day_start_hour | int | 日付が切り替わる時刻（0〜6時、既定 4）。⑦設定で変更できる |
| grumble_enabled | bool | ぼやきを表示する（既定 true） |
| grumble_push | bool | 通知でもぼやく（既定 false） |
| reminder_time | time NULL | 毎日のリマインドの時刻（NULL ならリマインドしない） |
| onboarded_at | timestamptz NULL | オンボーディングを終えた日時 |

### habits（習慣）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | |
| user_id | FK | |
| name | text | |
| note | text NULL | 補足 |
| period | enum `daily` / `weekly` / `monthly` | 周期 |
| times_per_period | int NULL | 週次・月次の**チェックのみ**の習慣の回数の目標（例：週3回）。日次と量の習慣では NULL |
| record_type | enum `check` / `quantity` | チェックのみ／量も記録 |
| unit | text NULL | 量の単位（回・km など） |
| quantity_target | numeric NULL | 量の目標。日次は1日の目標、週次・月次はその期間の目標。NULL なら目標なし |
| input_mode | enum `total` / `increment` NULL | 量の入力のしかた（合計を入力／回ごとに足す） |
| archived_at | timestamptz NULL | NULL 以外なら「過去の習慣」 |
| sort_order | int | 一覧での並び順 |
| created_at | timestamptz | |

### entries（記録）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | |
| habit_id | FK | |
| user_id | FK | 権限チェックと集計のため、重複して持つ |
| date | date | 記録した日（ユーザーの暦の日付） |
| quantity | numeric NULL | チェックのみの習慣では NULL |
| created_at | timestamptz | |

- **チェックのみ**・**合計を入力**の習慣：`(habit_id, date)` で一意にする（1日1行。合計の入力では上書きする）。
- **回ごとに足す**の習慣：1日に複数行を持てる（⑧-b の記録の一覧に1行ずつ表示する）。
- 週次・月次の習慣も、記録は日付つきで持つ。①-b の曜日の四角は「その日に記録があるか」を表す。
- チェックを外したときは行を削除する（論理削除はしない）。

## 3. 日付と期間

- **日付が切り替わる時刻**：ユーザーのタイムゾーンで **既定 4:00**。`day_start_hour` で変更できる（例：4:00 にした場合、11/2 の 2:30 の記録は 11/1 扱い）。
  - 設定を変えても、保存済みの記録の日付は変えない（以降の記録にだけ効く）。
- **週**：`week_start` から始まる7日間。設定を変えると、過去の週の集計も新しい設定で計算し直す。
- **月**：暦の月。
- **期間の達成**
  - 日次・チェックのみ：その日に記録がある
  - 日次・量：その日の合計 ≥ `quantity_target`（目標なしなら、量が 0 より大きい）
  - 週次・月次・チェックのみ：その期間に**記録のある日数** ≥ `times_per_period`
  - 週次・月次・量（目標あり）：その期間の**量の合計** ≥ `quantity_target`
  - 週次・月次・量（目標なし）：その期間に1日でも記録があれば達成
  - **量の習慣は回数を持たない**。目標はすべて量で表す（⑤ の「目標」ブロックで、記録方式に応じて回数か量のどちらかを入力する）
  - ※ デザイン①-b ではランニング（量の習慣）の行を「2 / 3 回」と表示しているが、量で判定するので「6.2 / 10 km」の表示に変える必要がある（[open-questions.md](open-questions.md)）。
- **目標超え**：量の合計 > `quantity_target`。超えた分を「+15」のように表示する。

## 4. 習慣の設定を変えたとき

- **【再検討】** MVP では設定の履歴を持たず、**過去の期間も現在の設定で計算し直す**。
  - 例：日次の目標を 30回 → 40回 に変えると、過去に 35回 記録した日も「未達成」になる。
  - 記録は生のデータで持っているので、あとから設定の履歴テーブル（適用開始日つき）を足せば、変更前の設定で計算する方式に移行できる。
- 周期（日次 ⇄ 週次 など）の変更も、MVP では上と同じ扱いにする。

## 5. 連続記録（streak）

- 達成した期間が途切れずに続いた数。日次は「日」、週次は「週」（`4 WEEKS`）、月次は「月」（`8 MONTHS`）で数える。
- **いま進行中の期間**（今日・今週・今月）は、まだ達成していなくても連続を途切れさせない。達成していれば数に含める。
- 過去の習慣にしていた期間は未達成とみなす（戻しても連続は復活しない）。**【再検討】**
- **最長連続**（③）：すべての期間の中で最も長い連続。
- **自己ベスト更新中**：いまの連続 = 最長連続 かつ 2 以上。

## 6. 草（ヒートマップ）

- 表示は1年分（⑥-a は年の切り替えあり、③は直近1年）。
- **習慣ごと**（③と、⑥-a の「習慣ごと」）：白黒の2値。その日に記録があれば黒。
- **すべての習慣**（4段階）：
  - その日に記録のあった習慣の数 ÷ その日に「現在の習慣」だった習慣の数 を割合 r とする（週次・月次の習慣も、その日に記録があれば1と数える）。
  - r = 0 → レベル0、0 < r ≤ 1/3 → レベル1、1/3 < r ≤ 2/3 → レベル2、r > 2/3 → レベル3。
- カードの「記録 ◯件」：その年に記録のあった（習慣, 日）の組の数。

## 7. 振り返りの文章

**【再検討】** 「連続3日以上で出す」「連続の長い順に並べる」で進める。それ以外の閾値も含めて、使いながら見直す。

### 達成していること

| 種類 | 出す条件 | 文の例 |
|---|---|---|
| 日次の連続 | 連続 3日以上 | 読書を 27日 連続で続けています |
| 目標超えの連続 | 目標超えが 2日以上連続 | 筋トレで 目標超え が 5日連続 |
| 週次・月次のペース | 2期間以上の連続達成 | ランニングを 週3回ペース で継続中 |

- 並び順：連続の長さが長い順（週次・月次は7日・30日に換算して比べる）。1つの習慣につき1件まで。
- ⑥-a には上位3件を表示し、残りは「ほか ◯件 すべて見る」にまとめる。

### もう少しで達成

| 種類 | 出す条件 | 文の例 |
|---|---|---|
| 連続の節目 | 次の節目（7・14・30・50・100・200・365日）まであと 3日以内 | あと3日続けると、読書が 30日連続 |
| 今期の目標 | 今週・今月の目標まであと 1〜2回で、期間が残っている | あと1回で、今週のランニング目標を達成 |

## 8. キャラのセリフの出し分け

詳細にこだわりはないので、この案で進める。上から順に判定し、最初に当てはまったものを使う。セリフは表情・場面ごとに複数用意し、日替わりで選ぶ。`{習慣名}` `{残り}` などの値を差し込むテンプレートにする。

| 優先 | 条件（記録画面のタブごと） | 表情 |
|---|---|---|
| 1 | その期間の習慣がない | （空の状態 E1／E2） |
| 2 | すべて達成した | happy |
| 3 | 22:00 以降で、未達成が残っている（今日タブ） | sleepy |
| 4 | まだ何も記録していない | grumpy（「まだ0個…ぼくと同じだね」系） |
| 5 | 未達成が残っている | grumpy |

## 9. デザインの未決定事項への推奨案

- **①の「＜」と②の役割の重なり**：②に一本化する（①は今日・今週・今月の記録だけを扱う）。
- **曜日指定・平日のみの周期**：MVP では作らない。必要になったら `habits` に曜日の指定を足す。
- **「達成していること」の並び順**：連続の長い順（7章）。

## 10. API と権限

- 全 API でログインを必須にし、`user_id` が一致する行だけを読み書きする（他人の習慣 ID を指定されても拒否する）。
- 「今日」はサーバーで `user_settings.timezone` から計算する（端末の時計だけには頼らない）。
- ＋の長押しによる即記録は、取り消しのトーストで元に戻せるように、追加した記録の ID を返す。
